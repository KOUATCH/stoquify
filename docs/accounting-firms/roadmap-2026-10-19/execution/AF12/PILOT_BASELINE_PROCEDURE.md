# AF12 pilot baseline procedure

**Prepared:** 25 October 2026. **Pilot enrollment:** not started. No real users have been enrolled or contacted by this execution.

## Preconditions

1. Complete the AF16 release-scope and go/no-go review before a production or real-client pilot. The user selected AF12 implementation before AF16; that sequencing does not qualify an expanded release.
2. Select consenting firms and client engagements with named mandates, assignments and an agreed observation scope. Confirm that pilot participants understand private notes, client-facing conclusions and the meaning of publication.
3. Have an accounting reviewer inspect the source/workpaper tie-out and sample advisory narrative. The product's independent review state is a workflow control, not a substitute for professional judgment or an audit opinion.
4. Record the metric version, included client periods, accounting calendars, UTC windows, inclusion/exclusion rules, operating context and known off-platform channels. Select comparable work rather than favorable completed cases.

## Establish the baseline

Use one complete monthly workflow cycle before any benefit claim. Collect the five measures in [METRIC_DICTIONARY.md](METRIC_DICTIONARY.md), preserving measured/eligible/missing counts and rejected-source cases. Include incomplete cases and failed reads in the research record. Record manual work outside Stoquify separately with the participants' agreement; do not infer it from page visits or login frequency.

Ask the accountant to trace each selected observation to its exact workpaper evidence ID/hash, explain the conclusion, identify the action owner/date, and distinguish client agreement from financial approval. Ask the client to locate the agreed actions and explain the publication status. Record task completion, errors and uncertainties without collecting unnecessary personal data.

Time active work only through a separately approved study method. The implemented metrics measure elapsed waiting/processing spans and deliberately return null active work time. Do not subtract overlapping request waits from close duration.

## Follow-up cycle and interpretation

Repeat the same observation and cohort rules for the following cycle. Disclose client mix, staff availability, transaction volume, evidence availability and period changes. Report denominators, coverage and missingness alongside any externally calculated comparison. Do not compare different currencies by summing balances; AF12 does not perform FX conversion.

Validate apparent improvements with the participants: fewer request touches can mean better evidence, missing requests, or off-platform work. Faster acceptance can reflect a simpler period rather than better software. An activated engagement is not proof of onboarding success or retention. Do not rank staff or infer firm profitability from these measures.

## Pilot exit evidence

- Current AF16 release decision and agreed cohort/window definitions.
- A reconciled reviewed pack, independent narrative review and attributable client agreement/publication.
- Missingness and source-limit reports for both periods, including unsuccessful cases.
- Reviewer and client task observations, with documented unresolved issues.
- A reviewed value statement based on observed customer work; no synthetic ROI or unsupported causal claim.

AF13 economics, AF14 assistance and AF15 packaging remain separately gated. The smallest justified next step is AF16 core/expanded-scope qualification and this baseline protocol, not an automatic optional-phase implementation.
