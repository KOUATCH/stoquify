# AF05 pilot training notes

Updated 20 October 2026. Training guide for a separately authorized synthetic or real pilot; this document does not authorize enrollment or production promotion.

## Firm manager

- Begin in Accountant Access → Firm engagements. The client must first give you a named mandate.
- Prepare a draft with the agreed dates and scope. Ask the client to grant each worker their own named mandate using Client mandates.
- Assign, explicitly enroll, then activate. Read each member's consent and assignment state separately.
- Before handover, inspect the authorized work summary. Client-recipient work stays with the client; review-team work stays in the existing review queue.
- Replacement removes the old assignment's managed access. The incoming person needs their own consent and, where indicated, explicit enrollment.
- Use suspension for a temporary stop. Ending is permanent. Review retained history after either change.

## Client owner

- Grant only the intended named accountant, using signed consent evidence and an expiry.
- The register now identifies individual accountants, not just the firm name.
- Revoke the intended person's mandate when access should stop. For renewal, issue fresh consent and a new expiry; tell the firm to enroll the new mandate.
- An invitation being queued or sent does not mean it has been accepted. Failed delivery can have a scheduled retry; deferred or exhausted delivery needs an operator.
- Do not create another invitation to work around delivery delays. Refresh the existing delivery panel.

## Preparers and reviewers

- Keep the existing home account. Do not create a duplicate identity or move organizations to join an engagement.
- Use the existing accountant portfolio and evidence desk. Management labels and scope names do not authorize posting, payment, export or independent review.
- After replacement, expiry, suspension or revocation, stop using old links and refresh current authority. Original evidence attribution remains retained.

## Recovery and operator checks

Confirm your password when prompted. After an uncertain response, retry the retained command before starting another change. For a stale version or business denial, refresh and inspect the current mandate, assignment dates and scope.

Before a production rollout, confirm AF03/AF04 migrations and restrictive readers/writers are deployed through the authorized release process. AF05 itself adds no schema migration. Retain managed access enforcement and read-only history if hiding the setup UI during rollback.

Observe action failures, identity failures, version conflicts, partial coverage and invitation delivery separately. Do not infer consent from notification delivery or certify accounting results from these workflow tests. AF16 owns release/pilot qualification.
