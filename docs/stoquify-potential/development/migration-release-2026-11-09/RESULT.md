## Financial observations

The migrated service chain posted a 10 XAF sale with 6 cash and 4 customer credit, collected 4 through the bank rail, and independently reversed the collection. Receivable due was `4 → 0 → 4`; bank was `0 → 4 → 0`. Stock remained four units valued at 16 after the sale; revenue was 10 and cost of goods sold was 4. Collection and reversal retained separate balanced journals and source evidence. Retry, concurrency and injected failure tests passed without duplicate or partial financial effects.

Close invalidation tests use expressly synthetic sentinel certification records. They prove source-change/invalidation behavior, not creation or invalidation of an earned, reviewed close certificate. The zero-tax synthetic chart/opening stock fixture is not a Cameroon statutory setup.

## Findings and corrections

- Qualification instrumentation initially compared a PostgreSQL network address with its CIDR suffix and assumed a trigger name could exceed the server's 63-byte identifier limit. The harness now checks the exact server representation, table, function and enabled state. No SQL migration or financial guard was changed.
- A populated-upgrade startup attempt waited on an inherited Windows process output handle after PostgreSQL was already ready. The verified owned instance was stopped, the unsuccessful attempt was archived, and only the harness's PG-control standard streams were corrected. A new uniquely named target is used for the retry.
- The first clean offline install lacked the cached public `zod` registry metadata, despite having all pinned package blobs. Only the exact integrity-verified cached metadata was imported into the owned cache; plain `npm ci` then passed. No `--force`, peer-policy override or lockfile change was used. Both attempts remain retained.
- Prisma generation initially tried a non-loopback lookup and was blocked. The retry used the CLI's supported explicit engine paths for generation only, with checksum-bound cached Windows binaries matching the locked engine revision. The generated default client and its default runtime DLL were verified; runtime overrides are not required. No network/checksum guard was disabled.
- Strict restore comparison found 13 CHECK-definition text differences among 1,130 constraints: redundant AND grouping and one array-cast deparse. No application/schema mutation was used to make them match. PostgreSQL itself reparsed each source/restored pair into identical TEMP scaffolds, requiring exact equality with the restored definition; the transaction was rolled back. Every other compared profile matched exactly. The first failed receipt and its dump, row profiles and full difference set remain unchanged and bound by the passing supplement.
- The first actual artifact command refused missing private-upload originals before compiling. Git deliberately ignores `/public/uploads/`; the source snapshot retained the three tracked aliases and policy but omitted the three ignored originals. All original and alias bytes in the workspace match the policy hashes. The correction is a separate private asset supplement copied only to the candidate, with explicit hashes and archive provenance. The generic source capture, privacy policy and packager checks remain intact. The unsuccessful command is retained.
- The first sealed-runtime HTTP attempt applied all 121 migrations, seeded the reviewed synthetic fixture, booted and redirected an anonymous protected request. Its first authentication POST reached the driver's 20-second deadline. [The failed attempt](artifact-http-attempts/01-cold-auth-timeout/ARTIFACT_HTTP_SMOKE_RESULT.json) is retained; application/PG shutdown and unchanged artifact verification passed. A separate [sealed native diagnostic](SEALED_NATIVE_DIAGNOSTIC.json) loaded the actual Argon2 and Prisma modules from the artifact and verified 16 relevant dependency files. A mocked transport diagnostic passed with exact body/hash, origin/forwarded headers and secure-cookie preservation. Neither diagnostic qualifies real authentication; a new database/target is used for the measured real retry, with one bounded cold-request deadline increase.
- The [second HTTP attempt](artifact-http-attempts/02-streamed-recovery-status/ARTIFACT_HTTP_SMOKE_RESULT.json) passed real wrong-password rejection, secure sign-in, persisted actor/organization, protected-route SSR and session deletion. Its status-only revoked-route assertion failed. Next 15 supports recovery through streamed redirect metadata; the revised check requires the exact same-origin recovery target/callback and absence of the protected main element, with negative parser fixtures. The installed version's implementation was inspected alongside the [official redirect contract](https://nextjs.org/docs/15/app/api-reference/functions/redirect). No application auth check was weakened.

The final fresh HTTP run passed every retained assertion. The prior attempt measured a 22.8-second first wrong-password request, exceeding the original 20-second driver deadline. These local cold/warm measurements explain the test-budget correction; they do not establish a production latency objective. Revoked access was denied through the actual Next recovery metadata, with the protected main element present on authorized pages and absent after revocation.
- Generated qualification evidence changed while the source was being frozen. A bounded evidence-only review and one explicitly reviewed test-file amendment were retained; application, migration, hook and configuration drift received no blanket exception.
