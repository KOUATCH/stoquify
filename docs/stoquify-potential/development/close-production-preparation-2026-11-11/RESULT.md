## Blockers fixed

1. **Invitation worker tenant and lease authority.** The worker previously allowed missing tenant scope and settled by request/worker ID without identifying the current attempt. An old acknowledgement could therefore affect a reclaimed lease using the same stable worker ID. Claim, reservation and settlement now bind organization, event, attempt and execution ID, with metadata/update-time comparisons where appropriate. A losing generation returns `LEASE_LOST`; duplicate processing observes the durable reservation. SQL NULL and JSON null are handled through Prisma's supported `AnyNull` filter.
2. **Uncertain delivery and crash recovery.** Dispatch is durably reserved before contacting the provider. Timeouts, transport exceptions, 5xx, 408/409 and missing acceptance IDs are treated as unknown outcomes and held for operator review. Reclaimed legacy work without reliable dispatch evidence is also held. Explicit retryable non-send results retain bounded retry behavior. A failed local settlement after an accepted send rolls back its event/audit changes and retains an unknown outcome rather than blindly sending again. No schema migration or automatic legacy-data repair was introduced.
3. **Private worker startup and failure visibility.** The CLI now preloads the existing Node `server-only` shim and invokes the installed local ts-node entry through Node, removing the implicit `npx` resolution/install fallback. Exceptions produce bounded generic errors. Structured queue results remain available, and `UNCONFIRMED` returns exit 1. Exit 0 means batch processing completed; it is not proof that each message was sent or delivered. `DEFERRED`, `PROCESSING` and `LEASE_LOST` retain their explicit queue/ownership meanings.
4. **Worker qualification missing from production admission.** The readiness checker now requires separate worker evidence tied to the candidate source, exact dependency lock, platform/architecture/Node runtime, native/runtime qualification and both delivery capabilities. The scheduler must identify that exact worker artifact. The current web-only artifact digest cannot be reused as the worker artifact identity. This is offline admission of independently reviewed records; it does not build a worker package or authenticate external records.

The updated [deployment runbook](../../../release/HARDENED_CLOSE_PRODUCTION_DEPLOYMENT.md) includes these requirements, migration 123's writer-quiescence/locking precautions, worker status interpretation, and queue/encryption-key rotation constraints. Public configuration defaults remain disabled. Existing unrelated working-tree edits were preserved; no commit or merge was made.
