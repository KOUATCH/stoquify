### Storage scope and operator recovery

An IndexedDB acknowledgement means the event committed to that browser profile. Server acceptance means the server retained the event, but does not mean a sale was finalized. Server replay acknowledgement means the durable sale and replay evidence exist. The Chromium and PostgreSQL suites verify these boundaries separately; they are not a single full-application browser-to-server test.

Strict IndexedDB commits do not survive total browser-storage deletion, device loss or disk loss. The queue detects missing IndexedDB evidence when its independent localStorage marker survives; deleting both can erase that detection evidence too. An independent durable copy is required before promising survival of total local-storage loss.

For an unknown attempt, retain its original queue/event/commit identifiers and payload. Reopen the same browser profile, let a stale lease expire, and reconcile server state using the original identifiers. A recorded sale should recover its receipt; it must not be submitted under a new sale identity. Preserve quarantined bytes and conflict evidence for operator review. If local storage is lost, inspect the server's retained event/commit records and an independent copy; if neither exists, do not claim the sale or acknowledgement was recovered.
