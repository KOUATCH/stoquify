## S10 — POS lease and recovery cost

Current source showed `usePOSCheckoutLifecycle` calling acquisition every 20 seconds. Each acquisition enumerated historical pending requests, resolved them individually, and loaded parked carts inside a serializable transaction. The August 9 graph's offline hook community 20 is discovery evidence only; the current hook/service/transaction source establishes this behavior.

The user delegated workload selection. Assumptions: 4 active tills for a small site, 16 for a larger site/multi-site burst; 10 retained attempts and 50 parked carts per cashier as an operational backlog; 100/500 as stress. Simultaneous renewal bursts are deliberately conservative. Provisional target: p95 <=250 ms, zero failed renewals, retained recovery access. These are synthetic workload assumptions, not measured customer percentiles or a hosted SLA.

### Evidence-backed changes

- Added a permission-checked renewal action with server-derived organization/actor. Renewal checks active shift/terminal authority under row locks and updates only the current, unexpired lease. It cannot take over an expired or foreign lease, clear pending intent, or settle a sale.
- Renewal uses READ COMMITTED with shared locks on the shift and terminal, plus the workspace compare-and-set. This addresses observed serializable predicate conflicts between unrelated tills on small tables while fencing closure/reassignment. Acquisition and financial transactions retain their existing serializable behavior.
- Normal heartbeats renew only the lease. Startup, reconnect/focus, explicit refresh, cart commands and a five-minute sweep retain recovery access. Delayed responses after offline/scope changes cannot restore stale authority. Renewal does not clear snapshots or rejected-command messages.
- A real stress run exceeded the existing 15-second acquisition transaction limit. Automatic reconciliation now processes the current checkout plus at most 20 historical requests. A tenant/cashier-bound keyset continuation advances past unresolved requests; the browser carries it between recovery passes. Pending requests and parked carts remain listed. Unknown intent is not deleted, and no new index/migration was introduced.

## S11 — Artifact validation before schema promotion

The previous package build ran migrations before lint/compilation. The default build now preserves secret preflight and lint/compile but does not invoke schema promotion. It remains a command with environment loading and filesystem effects, not a read-only audit.

`release:artifact` builds once, checks source stability and standalone runtime prerequisites, copies runtime/static/public files into a new directory, then writes a manifest binding source and content hashes. Existing destinations, links, secret-shaped files and incomplete standalone dependencies are refused. Verification requires a trusted manifest digest and matching source/migrations; changed, missing or additional files fail closed. Local files are content-verified, not inherently immutable or signed: trusted digest retention/immutable storage is an operator control.

`release:schema:promote` verifies the artifact, existing secret policy and explicit safe target, then holds a database-wide advisory lock while invoking the existing safe migration gate. Target/history/catalog checks, exact destructive approvals, baseline-bridge protections and post-migration health checks remain. Concurrent promotion fails closed; lock loss aborts the owned command tree. Prisma's migration lock remains enabled. Application deployment is a separate, unperformed action.

A safe reproduction also found `spawnSync('npm.cmd', ..., {shell:false})` returns `EINVAL` on this Windows runtime. The existing migration gate now invokes npm's JavaScript entry through Node on Windows, keeping shell execution disabled. `npm --version` through that path succeeded without executing migrations.

The CI readiness checker also incorrectly selected the earlier client-generation job's dummy URL as its database target (10/11 checks). It now reads database/auth settings from the verification job. The current contract passes 11/11, with eight tests covering isolation and negative cases. This is repository configuration evidence, not evidence that hosted CI has run.

See [artifact/schema runbook](../release/ARTIFACT_SCHEMA_PROMOTION.md). CI gains bounded artifact/gate unit tests; remote CI execution and branch protection were not claimed or changed through a provider API.
