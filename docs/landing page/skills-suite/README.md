## How To Use

Use the orchestrator first when the next phase is unclear. Use a focused skill when the task is already narrow, such as hero positioning, CTA repair, proof labeling, or accessibility/performance certification.

Do not run all implementation skills at once. The intended order is:

1. P0: positioning, CTA, proof boundaries, public-to-auth safety, first-page density, production baseline.
2. P1: buyer pathways, OHADA workflow visual, trust path, adoption clarity, use-case compression, analytics map.
3. P2: product pages, product demo, case studies, performance budgets, French polish, SEO cluster.
4. P3: controlled experiments, calculators, country variants, accountant/partner hub.

## Non-Goals

- Do not implement landing-page code as part of this docs-suite creation.
- Do not invent customer proof, metrics, testimonials, logos, certifications, or legal/accounting claims.
- Do not remove OHADA/SYSCOHADA specificity.
- Do not make the page generic while simplifying it.
- Do not install these skills globally unless explicitly requested.
