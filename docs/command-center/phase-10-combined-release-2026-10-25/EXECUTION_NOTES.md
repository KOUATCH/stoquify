## Root cause: redundant locale-cookie revalidation

The date diagnostic proved a real replacement before submission: the date input received native input/change events with 2026-11-01, then became disconnected and its replacement was empty within one second. No empty date was submitted by this diagnostic. The generated server-action manifest identifies the repeated requests as getCommandCenterFollowUps.

Inspection of the installed Next 15.5.27 request-store, mutable-cookie adapter and action handler shows that middleware-set cookies are merged through mutable cookies, marking pathWasRevalidated and requesting a replacement server component tree. middleware.ts wrote STOCKFLOW_LOCALE on every request even when its value already matched. This caused read actions to replace the protected subtree, which correctly discarded private draft state but repeatedly restarted follow-up reads.

The correction writes the locale cookie only if missing or different from the requested locale. Locale request headers, security policies, authentication, rate limits, fresh authorization and protected-snapshot unmounting remain unchanged.
