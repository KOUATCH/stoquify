# Stoquify Referral-Worthy War Plan Prompt

```text
Act as a multidisciplinary principal review team: system architect, cyber-security architect, senior frontend engineer, UI/UX specialist, product strategist, business logic analyst, and SaaS growth advisor.

Act also as a senior Stoquify execution program office responsible for turning strategy into implementation-ready skills, phases, artifacts, and verification gates.

Use every relevant document in:

docs/referrals/

as source material, especially:
- referral-worthy-platform-features-report.md
- stoquify-referral-worthy-execution-roadmap.md
- stoquify-referral-worthy-executed-roadmap-report.md
- stoquify-referral-worthy-roadmap-architect-prompt.md

Your task is to design a complete execution war plan for realizing the referral-worthy Stoquify roadmap. The plan must turn the recommendations into a coordinated implementation program that can move Stoquify toward becoming a differentiated, sticky, trust-centered SMB operating platform.

Do not merely summarize the documents. Build a serious execution blueprint that includes product strategy, architecture, domain sequencing, specialized agent/skill design, implementation phases, verification gates, and delivery artifacts.

Use all appropriate expert lenses and available skills, including:
- product strategy and SaaS growth
- enterprise architecture
- service-owned business truth
- POS and cash control
- inventory loss prevention
- payment reconciliation
- accounting/OHADA/SYSCOHADA compliance
- payroll and employee trust
- accountant collaboration
- fraud/leakage detection
- AI copilot guardrails
- WhatsApp/mobile automation
- UI/UX workflow design
- RBAC, tenant isolation, redaction, audit, and release gates

If local Codex skills are relevant, identify which skills should be used or created. For any proposed new skill, define its name, purpose, trigger, responsibilities, input files, output artifacts, verification gates, and success criteria.

Structure the final output as follows:

1. Strategic War Objective
   - Define the end-state Stoquify must reach.
   - Explain what "referral-worthy" means operationally, not emotionally.
   - Translate the roadmap into a concrete execution mission.

2. Source Document Synthesis
   - Extract the core promises from all docs/referrals documents.
   - Identify overlapping themes, gaps, dependencies, and contradictions.
   - State which recommendations should be executed first and why.

3. Execution Pillars
   - Organize the roadmap into major execution pillars:
     daily business truth, cash leakage radar, accountant portal, statement hub, inventory control, compliance readiness, financing passport, copilot/WhatsApp automation, and referral loops.
   - For each pillar, define user pain, target users, service-layer requirements, UI requirements, data requirements, security controls, and expected business impact.

4. Specialized Skill Suite
   - Design a set of targeted Codex skills or agent briefs needed to execute the roadmap.
   - Each skill must be narrow, implementation-ready, and aligned to one execution pillar.
   - Include proposed skill names, descriptions, trigger phrases, required evidence to inspect, files/folders likely involved, expected outputs, tests, and release gates.
   - Include an orchestrator skill that coordinates the full roadmap.

5. Phased Delivery Plan
   - Break execution into phases: foundation, daily truth, leakage controls, accountant close, external collaboration, financing readiness, automation, and network effects.
   - For each phase include scope, dependencies, implementation tasks, risks, success criteria, artifacts to save, and verification commands.

6. Product And Technical Architecture
   - Design the business event spine, evidence layer, action center, read models, notification layer, external sharing model, RBAC/redaction model, audit model, and copilot safety model.
   - Keep truth service-owned and tenant-safe.
   - Prevent dashboard-only or UI-derived business truth.

7. UX And Habit Loops
   - Define daily, weekly, and monthly workflows for owners, managers, cashiers, accountants, payroll operators, suppliers, customers, and lenders.
   - Explain how each workflow creates retention, trust, and referrals.

8. Implementation Backlog
   - Convert the war plan into epics, user stories, acceptance criteria, and first implementation tasks.
   - Identify the first 10 tasks that should be started immediately.
   - Include recommended file/report locations for saved outputs.

9. Verification And Release Gates
   - Define focused tests, policy gates, route/service checks, UI smoke checks, report artifacts, screenshots, and data-quality checks needed for each phase.
   - Include how to prove that each feature is safe, useful, and referral-worthy.

10. Monetization And GTM Alignment
   - Map features to free, core, professional, premium, accountant-firm, and enterprise packaging.
   - Explain how accountant-led referrals, supplier/customer links, financing partners, WhatsApp workflows, and professional proof packs drive growth.

11. Risks And Controls
   - Identify risks around scope, compliance drift, weak data, false fraud alerts, AI hallucination, external data leakage, adoption friction, and operational complexity.
   - Define practical guardrails for each risk.

12. Final Execution Recommendation
   - Recommend the best first 30, 60, and 90 days of work.
   - State what should not be built yet.
   - Conclude with the clearest path to making Stoquify stand out from ordinary POS/accounting/inventory tools.

Non-goals:
- Do not propose vague features without implementation paths.
- Do not ignore RBAC, redaction, audit, tenant isolation, or service ownership.
- Do not treat WhatsApp or the AI copilot as the source of truth.
- Do not widen into unrelated platform refactors.
- Do not create generic SaaS advice.

The final output should be a founder-and-engineering-ready execution war plan that can guide actual implementation and skill creation.
```
