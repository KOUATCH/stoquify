## Exact runtime acceptance cases to retain

1. With synthetic tenant A and B and two locations, create owner, site-A manager/cashier, stock operator, finance reviewer and accountant. Record actual permissions, role organization ownership and scope policy. Do not substitute super-admin for representative roles.
2. Exercise revoked session with previously valid cookie, inactive/locked user, stale active org and removed role. Request new reads/writes and retained downloads; verify server rejection and no foreign data in response/error/audit. Repeat via browser/API against persisted state.
3. Remove an accountant grant and test expiry at the exact boundary and scheduled access. Check READ_ONLY read succeeds while EXPORT/REVIEW fail, including a fresh-auth mismatch and another client's ID. Agree behavior for an in-flight operation and measure the race rather than claiming an atomic guarantee.
4. Attempt another tenant's batch/order/receipt/period/asset/job and an unassigned location. Check denial before reads, writes and object fetch. Record each route, role, locale and fixture ID, and independently inspect authorized synthetic records for no mutation.
5. Check enforce-mode unavailable/read-only modules for read, new write, export and job separately. Preserve supported retained-result access and explicit data rights. A green helper is insufficient where no entry-point gate is wired.
6. Issue an export token, then remove permissions/revoke session, switch actor/tenant, expire job/token, tamper token/chunk, delete wrapped key or provider object. Check the deployed delivery path, bytes returned, logs and final file hash. Include public receipt and legacy direct-static cases with their distinct sharing model.
7. Rehearse recovery and controlled worker replay per protocol; document actual results, source/config fingerprints and cleanup. No deployment evidence exists from P04.
