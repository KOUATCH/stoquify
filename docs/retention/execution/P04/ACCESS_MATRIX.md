## Shared authority

`lib/security/rbac.ts:96–158` bypasses Better Auth's cookie cache, loads the active user by session subject, rejects inactive/deleted organization, locked/unverified account and stale session organization. Permissions come from current stored roles, not caller fields. The inspected membership model is the user's current `organizationId`; this is not a claim about every historical membership or role-assignment invariant.

`services/_shared/protect.ts:81–105` requires permission, applies a module gate **only when configured**, then checks supplied tenant candidates and invokes the handler with server context. `:183–204` only extracts named top-level/data tenant fields; it is not a recursive resource-ownership validator. A `handler-derived` opt-out requires the handler to overwrite caller authority and scope each resource. No universal location restriction or module enforcement should be inferred from use of `protect` alone.

## New test scope and what it proves

- Accountant tests evaluate the service's actual Prisma query against synthetic two-client/two-accountant records, then mutate grant state. They prove predicate construction and capability branching, not PostgreSQL query execution or an atomic concurrent revocation barrier.
- Location tests filter two tenants, two managers and inactive/deleted sites using the actual query, and check removal on a later resolution. They do not extend that helper to purchasing or inventory writes.
- Inventory export tests use the existing in-memory outbox/artifact store and actual crypto helpers, injected secret and fixed clock. Current permissions are supplied by the test. They prove helper admission/denial and no artifact reads on denied requests, not that a deployed HTTP route supplies fresh permissions.
- Module tests use current catalog and all derived dependency grants, then restrict inventory to read-only. Read succeeds, write/export/job deny even with RBAC `*`. This characterizes existing policy; it does not decide post-cancellation archive rights or add new commercial restrictions.
- Existing RBAC tests exercise fresh session lookup, revoked-session denial, authority lookup by subject rather than email, narrow stored permissions, and cross-org denial even for wildcard users.

No production authority helper was replaced. No demonstrated failure of these scoped authority cases required a production fix. Coverage/integration gaps remain explicit; passing cases do not close them.
