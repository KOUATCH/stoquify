# P05 — Checkout failure matrix

Run: 13 October 2026. Evidence classes: S = inspected current source; M = mocked/pure tests; D = real PostgreSQL; B = rendered browser. **D and B were not run.** [Result](RESULT.md) and [verification record](evidence/VERIFICATION.json) bound every claim below.

## Current path and dependencies

The protected [tender action](../../../../actions/pos/tender.actions.ts#L35) derives organization/cashier authority, prepares the retained intent, then calls commit. [Checkout preparation](../../../../services/pos/checkout.service.ts#L121) validates the session/lease and persists the original request. [Commit](../../../../services/pos/pos.service.ts#L2210) first recognizes an existing result and validates its scope/hash, then admits new work under the lease, module, draft, stock and financial controls. Durable result finalization belongs to the financial transaction; receipt completion follows it. [Recovery](../../../../services/pos/pos.service.ts#L2149) reads original evidence in a RepeatableRead transaction and does not complete receipts or repost the sale.

The client [retains the original request before submission](../../../../components/pos/ProfessionalPOSSystem.tsx#L1129), using [sessionStorage with read-back](../../../../lib/pos/pending-sale.ts#L7). The server checkout workspace retains intent independently. A new lease is supplied separately; the original operation ID/payload must survive uncertainty. Session storage is not a cross-device backup guarantee.

## Chosen defect and scope

[The payload hash](../../../../services/pos/pos.service.ts#L2007) intentionally does not include the operation key. The old retained-intent guard compared only that hash. With a valid lease, the service could therefore admit a different `clientCommitId` carrying the same request body. The failing test used otherwise valid prices/tax data, reached a successful mocked sale, and demonstrated the missing identity check rather than an earlier validation error.

The [fix](../../../../services/pos/pos.service.ts#L2237) adds one identity predicate and an explanatory comment. It leaves hash versioning, schema, existing recorded replay, money arithmetic, entitlement, period controls, stock kernels and receipt completion unchanged. No data migration is needed. The new [PostgreSQL case](../../../../services/pos/__tests__/pos-full-commit.postgres.test.ts#L134) compares financial snapshots before/after rejection and replay; it remains **NOT_RUN**.
