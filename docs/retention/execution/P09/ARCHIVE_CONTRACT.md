# P09 — Authorized archive contract

18 October 2026. **Proposed contract with an executable synthetic profile; no production archive endpoint or approved cancellation policy.** This packet implements P09 only. The proposed P01 Cameroon retail/distribution envelope remains unapproved for live use.

## Boundary and version

The reusable [schema and validator](../../../../services/organization/authorized-archive-contract.ts) live with organization-level services, without importing persistence, auth, services, network or filesystem extraction. Version `stoquify.authorized-archive/1-draft`, profile `p09-synthetic-retail`, is deliberately accepted only for `source.basis=synthetic-fixture`. P16 must introduce a reviewed production profile and domain DTOs; do not relabel this fixture as a tenant exporter. The validator is a contract checker, **not an authorization grant**, generic backup restore tool, ZIP extractor, or malware scanner.

Keep ordinary role-scoped reports redacted. An authorized archive is a separately approved customer-owned scope. Reuse current domain owners for extraction and export safety/audit controls for delivery; do not serialize Prisma objects wholesale. Existing background inventory infrastructure supplies useful checkpoint/crypto patterns but is not a whole-tenant archive implementation.

## Envelope and integrity

| Field | Contract |
|---|---|
| Identity | Schema version, profile, archive ID, organization ID; UTC generation timestamp. Unknown schema keys/versions fail validation. |
| Source | Revision and snapshot ID. Synthetic basis is mandatory in this profile. Production requires immutable candidate identity, consistent database snapshot/watermark and object evidence tied to it. A generation timestamp alone is insufficient. |
| Authority | Owner ID, decision reference, policy version and explicit sensitive field scopes. The caller supplies independently trusted organization/owner/decision/sensitive-scope expectations; the manifest cannot authorize itself. This comparison does not verify a live session or consent. |
| Coverage | Exactly one entry for each of the 20 categories in PORTABILITY_COVERAGE: included, excluded or blocked, with nonempty reason and accountable role. Included means only the declared DTO subset. At least one file descriptor, including a zero-row dataset if applicable, is required for each included category. Credentials must be excluded. |
| Completeness | Fixture is `partial`. Any blocked category prohibits `declared-scope-complete`. Even that label means declared scope only; its truth against the source database requires separate extraction reconciliation. Reclassifying a blocker as excluded requires approved scope, not an exporter workaround. |
| Files | Portable lowercase relative path, MIME type, exact UTF-8/binary byte length, SHA-256 and row count. JSON record arrays are in `records/`; attachment bytes are in `attachments/`. Attachment record count is zero; evidence records are counted separately. Unknown files, duplicates, missing bytes, mismatched counts/hashes and MIME/extension mismatch fail. |
| Controls | Total record count and per-currency transaction/debit/credit totals as decimal strings. The transaction total is a document control sum across sale and purchase, **not revenue or cash**. No cross-currency netting or conversion to JS Number. |

SHA-256 covers **the exact file bytes**, including whitespace/newlines, not a parsed/reformatted representation. The fixture JSON contains a manifest and file-content strings for convenient review; the reader turns those strings into UTF-8 bytes. Production packaging must additionally publish a detached manifest digest through an authenticated channel, bind scope/snapshot to the authorization/audit record, and document any signing/encryption mechanism. Hashes detect accidental change against trusted references; an attacker who replaces the manifest and bytes can recompute them. P09 does not establish authenticity or nonrepudiation.

Unknown fields are rejected at every structured record/envelope level. No arbitrary metadata bag is allowed. Reference-only or missing attachments are not presented as delivered evidence. Paths cannot contain traversal, backslashes, drive prefixes, remote URLs or arbitrary executable extensions. No archive code fetches those paths. P16 must separately enforce extraction size/entry/decompression limits, safe filenames, content-type validation and attachment content review; P09 handles a small in-memory fixture only.

## Relationship and reconstruction rules

The current strict DTOs cover locations; roles and principal references; organization currency/timezone/locales; an item with translated names and unit metadata; customer/supplier parties; evidence-to-attachment links; sale/purchase documents; journal lines; approval references; and stock opening/movement/closing positions. This is 11 record kinds, not the full production model set.

Archive IDs are unique within a package. Production must use namespaced record identities where source model IDs collide and retain exact `(sourceModel, sourceId, organizationId)` mapping for every entity. The fixture explicitly preserves SalesOrder/PurchaseOrder source identifiers. Links must target the expected record kind in the same tenant. Transactions require party/item/location/actor and at least one evidence reference. Evidence must resolve to declared delivered bytes. Principal role/location links and approval reviewer/source/evidence links must resolve. Role membership is historical context; importing it must never provision credentials or grant current authority automatically.

Amounts and quantities use base-10 strings. Currency, unit code, declared scale, locale, timezone and both effective/recorded timestamps travel with their relevant records. The fixture uses XAF values with two decimal places and synthetic account codes solely to exercise exact arithmetic; this is **not a statutory rounding or OHADA mapping decision**. The checker verifies monetary totals, per-document debit/credit balance against document total, unit identity, and stock opening + movement = closing, with movement reconstructed from the fixture sale/purchase quantities. Production must validate currency/unit scale and conversions, tax/mapping versions, valuations, correction links and time boundaries through the owning domains. Missing/unknown values must remain unavailable, never guessed as zero.

The independent reader in the [tests](../../../../services/organization/__tests__/authorized-archive-contract.test.ts) uses handwritten expected totals and Node crypto/BigInt, without the validator/schema/decimal helper, to reconstruct the known fixture. Negative cases reseal altered files and counts to show that intact hashes do not hide lost references or incorrect balances. This is not restoration into another product or reconciliation against a live database.

## Privacy, ownership and retention

Customer-owned sensitive fields need an explicitly approved field scope, purpose, recipient and decision reference. This profile admits only `party.contact` / contact email, and requires both manifest declaration and independent caller approval. Other contact fields, tax identifiers, bank details, private notes, payroll and unrestricted audit payloads are not authorized by this profile. P16 must specify field-by-field projections, not add a generic unredaction switch. Structured rejection cannot identify a secret pasted into an otherwise allowed name/description; production must avoid unconstrained payloads and review attachment/text classification.

Never include passwords/password history, session/access/refresh/receipt/supplier-portal tokens, OAuth credentials, MFA secrets, provider credentials, encryption keys/IV/tag material or executable worker payloads. Decrypt authorized customer attachments within the protected delivery service when appropriate; give customers useful file bytes and provenance, not server encryption keys or expiring private provider URLs. Retain original logical media IDs/hashes and state which source evidence could not be obtained. PictureAsset source contains sensitive encryption/provider fields and cannot be dumped wholesale.

Archive artifact expiry is distinct from source-record retention, legal hold and customer access after cancellation. Current inventory artifact TTL (default 24 hours, maximum 7 days) is an implementation setting, not a legal or commercial rule. No retention period, deletion approval or statutory obligation is established here. Named blockers and owners are in PORTABILITY_COVERAGE; P10 must resolve lifecycle policy and qualified review must establish applicable retention/deletion requirements. Do not delete source records or withhold customer data to enforce a commercial decision.
