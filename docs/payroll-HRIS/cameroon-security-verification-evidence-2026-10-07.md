# Cameroon HRIS/payroll: security and verification evidence

Date: 7 October 2026. Scope: assessment and implementation planning for private-sector SMEs with 10–250 employees. Source baseline: current local working tree; no deployed environment or immutable release candidate was verified. This supporting register informs the consolidated Cameroon-first blueprint; it is not another program roadmap.

Only this report was written by this audit slice. No application code, schema, configuration, database, credentials or plugin settings were changed. ECC `security-review` was read and applied selectively to the existing Better Auth/Prisma architecture; its generic installation, update, Supabase and blockchain examples were not executed or treated as project requirements. Legal conclusions and retention durations belong to the separately researched primary-source requirements matrix and qualified local review.

## Overall assessment

Retain the existing server authorization, tenant derivation, own-payslip controls, financial transition ledger and correction mechanisms. Their presence materially changes the plan: harden and prove existing controls instead of rebuilding a generic payroll CRUD system. The largest release gaps are authoritative country provenance, actual private-document delivery, explicit employer scope, current real-database/browser evidence and an operating model that can supply independent actors.

Two concrete scope defects were identified by source inspection. Manager authority is truncated before an individual employee is checked; the profile facade passes `limit: 1`, so even a second valid report can be denied. The directory facade also omits the requested `asOf` date from authority resolution while forwarding it to employee data projection. This mixes current authorization with historical data. Neither finding is a demonstrated live cross-tenant disclosure.

The source review did not establish a presently exploitable cross-tenant disclosure. That limited conclusion is not a penetration-test result. Database constraints, deployed triggers, actual roles, secrets, provider credentials, document storage and browser behavior were not live-tested.

The later HRIS page contract should specify denied/stale/unlinked employee states, explicit compatibility-manager labeling, safe archive status and step-up recovery. UI/UX Pro Max may improve hierarchy/focus/mobile interactions after those controls are fixed; it must not conceal a denied permission behind a zero count or turn an unavailable document/provider feature into a successful-looking action.

Measure improvements with denial-matrix coverage, unresolved leaked-field findings, false manager-denial rate at 2–250 employees, time to resolve an unlinked profile, and current DB/browser evidence age. Do not use total installed skills, mocked test count or one passing gate as the definition of Cameroon production readiness.
