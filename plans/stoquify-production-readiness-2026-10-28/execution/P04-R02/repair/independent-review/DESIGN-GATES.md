# Independent R02 repair design gates

29 October 2026. User-authorized local repair; reviewer owns only this review directory. No production asset transition, deployment, flag, migration, commit or push is implied. These are source-design constraints pending concrete patch and runtime review.

1. Preserve the existing API's current organization/session, dashboard-module and dashboard.read decisions. Both original API and legacy URLs reach the same authority boundary before bytes are opened. Cookie presence is insufficient. Do not silently broaden this repair into an item/location-policy change.
2. Production reads only `.private/uploads`; missing private root/file must not fall back to public. Development/test fallback may retain existing source assets behind the same guard, with explicit evidence that it is unreachable through static/optimizer bypasses. Preserve source originals and stored URL references.
3. Validate organization and filename as individual portable path components. Reject known symlink/junction ancestors and leaf, traversal, device/path syntax and ambiguous case collisions. Prefer a single opened file handle followed by regular-file validation and read, with non-following open where supported. Point-in-time lstat/realpath checks do not establish safety against arbitrary hostile concurrent ancestor replacement. Private runtime storage must remain operator-controlled, not tenant-writable.
4. Map originals to manifest-bound private runtime paths. Remove public copies from the new output by controlled selection, not by deleting originals. Inspect both explicit public input and any traced standalone duplicates. Conflicting copies or destinations fail before sealing. Verification must bind ignored source assets independently of Git source capture, validate paths before reading them, and reject public duplicates or missing/inconsistent private mappings.
5. Canonical and encoded/case legacy paths must either reach the authorized reader or fail without bytes. A plain after-files rewrite is insufficient while local public assets remain. Include actual routing policy in the HTTP fixture. Windows case behavior, percent-encoded namespace/separators, double encoding, repeated slashes, backslashes and malformed paths require observed outcomes, not normalization assumptions.
6. Private images must not enter shared optimization. Internal Next optimizer requests lack caller credentials; do not add credential forwarding. Old populated optimizer caches may bypass origin authorization. Either enforce a pre-cache URL restriction with tested normalization or leave old-cache cutover explicitly unresolved. Existing middleware excludes `/_next/image`, so it is not currently a cache boundary. Preserve ordinary public image controls.
7. Separate evidence: direct reader/unit tests; actual Next HTTP with synthetic authority; real signed-session qualification; production-mode private-root behavior; manifest/private artifact behavior; full current artifact runtime; hosted ingress/cache cutover. One lane cannot substitute for another. Failed before evidence remains retained.
8. Recovery preserves originals, hashes and reference continuity, and never restores public exposure as a rollback. Fresh isolated candidate identity is required after the preceding unrelated drift. Final acceptance depends on inspected patch and completed denial/positive-control receipts; this design record is not a pass.
