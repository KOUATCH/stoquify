Date: 24 September 2026. Browser actions used the available CUA browser tools only. No live charge, sale submission, refund, void, role assignment or credential change was performed. No session tokens, receipt bearer URLs or customer records are copied here.

## Environment and observations

- Restarted an absent local development server on localhost:3000 with isolated output `.next-pos-audit-dev`. Server output reported Next 15.5.23 ready. Initial Edge navigation first encountered connection refusal, then a long cold compilation and a redirect to English login for the terminal route.
- Repeated browser acquisition/state calls timed out (`DOMSnapshot.captureSnapshot`, `Runtime.evaluate`, and whole-call timeouts). Browser IDs changed after runtime reset; inventory was refreshed before selecting them again. One Edge retry reported that its debugger was unattached.
- The in-app browser eventually loaded `/en/dashboard/pos` using an existing accountant session. It showed permission-required content and withheld checkout because `OPERATE_POS` was absent. No permission or actor impersonation was introduced to bypass that boundary.
- The English denied state was inspected at requested 1440×900, 1024×768 and 390×844 viewport settings. Existing browser scaling produced measured CSS widths 1043, 742 and 282; document widths were 1032, 731 and 271. No horizontal overflow was measured in this state. A screenshot was emitted into the task at the narrow size; no standalone screenshot file was exported.
- `/fr/dashboard/pos` showed a French shell but English custom denial title/message. The route copy was corrected. A later DOM observation showed `Un accès au point de vente est nécessaire`, French guidance and the French dashboard return link. This is an observed correction, not just dictionary parity.
- The viewport override was reset. The POS tab was shown/retained for the user's proposed switch to an existing authorized POS account. A subsequent read still showed denial. Later browser state/navigation calls timed out again. Opening the POS URL in the task's browser panel returned queued status; this is not evidence that account switching completed.
- A separate English cash-drawer navigation was attempted without changing the user's POS tab, but timed out before a usable state was returned.
- After production compilation, another direct POS-tab observation again showed the corrected French denial state, not an authorized cashier session. A missing-token receipt smoke navigation was also attempted, but navigation/focus automation timed out before the page could be inspected; it is not a browser pass.
- A final fresh tab observation after configuration cleanup again showed the French permission-required title, guidance and dashboard return link. The user-proposed account switch had still not produced an authorized POS view. The existing tab was retained for that handoff; no checkout submission or new access assignment was attempted.
- At approximately 04:03 UTC, browser access recovered sufficiently to inspect the existing `/digital-receipt/pos-audit-missing` tab. Its title was `Receipt · Reçu | Stoquify`; the accessibility tree and screenshot showed English and French unavailable-link guidance without receipt data. This is a passing invalid-link smoke check only, not valid-token or print proof.
- The existing English `/en/dashboard/finance/cash-drawer` tab then displayed the authorized accountant drawer dashboard: location/period controls, current scope, drawer overview, movement, session reconciliation, journal and localized related links. This establishes successful read-only rendering for that actor and language, not mutation authority or all financial calculations. No fixture names, contact details, session identifiers or balance values are copied into this report.
- Its visible language link navigated to `/fr/dashboard/finance/cash-drawer`. The French shell rendered, but the drawer dashboard did not complete. A loading message remained during initial observations; a later DOM read still had no drawer section. No browser console error was returned. One fresh reload timed out and reset the browser runtime. French drawer rendering remains incomplete, not a passing dashboard or proof of a specific application defect.

## What remains unverified

The route matrix in `../verification-matrix.md` lists all 26 localized targets. Observations include the POS denied states, terminal login redirect, English accountant drawer dashboard and invalid-link public receipt view above. Authorized cashier/manager checkout, unvisited history/report views, long carts, split tenders, recovery dialogs, keyboard sequences, actual zoom behavior, print pagination, screen-reader use and full accessibility checks were not completed in this browser session.

The new public receipt page has focused rendering/access/privacy tests but no valid-token browser proof from this run. Tests never borrowed a live customer's token to manufacture that proof. Browser failures and missing role access are verification limits; they must not be converted to successful page checks or claims that all routes are broken.
