# POS modernization implementation

This continued run implements focused corrections across POS services, server actions, scoped hooks, checkout UI, terminal/drawer navigation and public receipts. The full workflow was traced; delivered, partial and unavailable journeys are distinguished in [workflow and architecture](workflow-and-architecture.md). It is not a framework replacement or production certification.

## User-visible results

- Checkout ownership and late-response handling are safer across disconnection, lease expiry, account/register changes and concurrent lifecycle commands. Losing authority clears obsolete cart-review acceptance. Original uncertain requests remain recoverable.
- Charge prerequisites and nearby recovery remain explicit. The earlier natural-height checkout, adjacent Resume action and truthful “reviewed” state are preserved and regression-tested.
- Drawer data follows the current actor and organization, with explicit permission denial and safe refetch behavior. Payment-history rows and totals now respect the selected location. Terminal-to-drawer links and locale-aware navigation are corrected.
- Expanding an open drawer session now shows “Non disponible” for a missing final balance instead of a misleading zero. Existing numeric balances retain their currency formatting; this follow-up changed only the display expression.
- Network/printer status no longer implies unsupported readiness. Terminal labels and the POS route's blocked-state copy are localized in English and French.
- Generated digital-receipt links now have a responsive server-rendered page with browser printing, EN/FR content, privacy headers, limited public fields and clear fiscal-state wording. Receipt display does not charge or post a sale.
