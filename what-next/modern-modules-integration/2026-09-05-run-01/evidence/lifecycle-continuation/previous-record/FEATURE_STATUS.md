## Operational catalogue versus proposals

Native workspace destinations exist for dashboard, inventory, sales, POS, cash accountability, accounting, close assurance, compliance, purchasing, payroll, finance, payment reconciliation, analytics, reports and settings. Individual destinations still require their route permissions and effective grants. Reports use the current analytics report destination and require its analytics boundary too.

Presence, commercial agents and content do not have supported current workspace destinations in this integration. Existing grants and unknown legacy values are retained; unavailable entries cannot be newly added as if operational. Administration is a retained core control boundary, not a newly invented employee workspace.

Standalone HRIS, assisted work, a separately packaged ledger kernel, external-ledger modes, new billing packages, country setup certification and provider provisioning remain proposals or external/domain work. The UI explains these boundaries instead of installing synthetic prototype state.

## Genuine remaining actions

1. On a real target, the operator must authorize/apply the two migrations, generate the matching client and restart the app in the controlled release window.
2. The commercial/tenant authority must supply any missing eligible grants through a governed source; configuration selection cannot provide them.
3. Domain owners must complete actual accounting, provider, payroll or country setup before operations requiring that setup.
4. Engineering must complete per-domain new-work versus continuation enforcement before offering operational deactivation. This is not a missing user signature and is not claimed complete.
