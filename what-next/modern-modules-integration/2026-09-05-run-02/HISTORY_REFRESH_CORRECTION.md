# History refresh correction

Two actual browser attempts loaded all 112 configuration records and displayed the old applied configuration at ordinal 107. Before reopening, the list returned to 25 rows while the History tab stayed selected. Neither attempt submitted a reopen request or created a draft. The receipts and screenshots are preserved in `diagnostics/HISTORY_VERIFICATION.md`. The upstream reason for Next replaying props was not established; the observable defect was the workbench unconditionally replacing appended pages whenever it received an `initialData` object.

The correction retains fetched pages only within the same server-derived organization, actor/permission key, configuration revision, active revision and latest lifecycle state. The permission key is a cache boundary, not an entitlement or authority supplied by the browser. Incoming authoritative entries replace matching cached entries. If a new first page is disjoint, the list and cursor reset so intervening newly created records cannot be skipped. Responses from an invalidated in-flight scope are ignored.

Historical command records are durable, but an operation's displayed lifecycle status can change. Older loaded pages therefore explicitly identify their statuses as snapshots in English and French. Refresh reloads current history; reopening always revalidates current authority and creates a new draft. Automatically discarding every older nonterminal row on each props replay would make those records difficult to inspect, so the UI exposes freshness instead of pretending the cached status is live.

The first focused run passed 15 checks and failed one new test assertion: a successful reopen correctly switched to Build, while the test attempted to load history without returning to its tab. The navigation assertion was corrected. The complete workbench and composition-service suites then passed **79/79** in 42.059 seconds, session `4363`, with machine-readable output in `evidence/history-refresh-full.json`. This includes scope changes, disjoint head, late response, preserved cursor/reopen and normalized server permission-key coverage.

This correction follows the recorded application-build attempts. Do not claim those builds tested these later source changes. Current-source typecheck (`89090`) and changed-file lint (`15146`) both exited 0; `evidence/HISTORY_REFRESH_VERIFICATION.json` binds the final sources.

The final real-browser run passed five observations with unchanged source and no page errors. All 112 records loaded through four additional pages; applied row 107 remained after capture and a 1.5-second settle. Genuine password verification reopened it as exactly one new DRAFT, raising the count to 113 while preserving the original record and full active/desired configuration. Useful first history took 13.589 seconds in this development run. `diagnostics/history-pagination-browser.json` and its screenshots retain this evidence; the first two failures remain separate. Parent visually inspected the applied-row and reopened-builder captures.
