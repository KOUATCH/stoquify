# AP history controlled CSV download — v76

## Delivered behavior

The previous prepare-export action accepted a browser-supplied row count and returned only a safety decision. The hook then announced ready without producing a file. The integrated flow now generates the actual filtered CSV, calculates the real row count, and records its content hash and scope in a mandatory audit. The browser verifies the received bytes before starting the download.

All matching rows are exported, including archived sources, rather than only the visible page. The export uses the v75 evidence-aware financial read model: document values stay separate from recognized movements; missing proof is UNAVAILABLE, never zero; current filtered invoice remainders and recorded payments remain separate by currency. The CSV contains a versioned manifest, organization, generated/recorded-through times, timezone, filter identity/hash, actual row count, watermark, financial basis, per-currency summaries and source/evidence references. It excludes notes and bank destination fields. It has localized EN/FR headers and scope guidance; stable evidence/status codes support interpretation across locales.

The default server read and the artifact audit share a RepeatableRead transaction. An audit failure prevents return of the artifact. The audit describes artifact generation, not confirmation that a user saved the file. No server-side permanent file archive is introduced. Retain the downloaded file if that exact extract is required later; retry generates a fresh extract with a new timestamp/reference, without changing financial records.

## Controls and limits

The action derives identity and organization from the verified session. Current AP read permission, report-export permission, purchasing module access and password assurance within five minutes are required. Module enforcement also exists in the export service. The action rechecks current authority after generation before returning private bytes, including identity/organization/session continuity. The module audit now names the actual export surface. The browser additionally rejects a result for another organization/actor and ignores late responses after close, filter change or identity change.

Client organization, rowCount, cursor and page-size overrides are rejected. Counts come from the server. The synchronous file path has engineering bounds of 5,000 rows and 8 MiB of CSV, with explicit rejection and narrower-filter guidance; it never silently truncates. These are implementation limits, not subscription terms or performance certification. Very large exports, query scaling and durable asynchronous export jobs remain outside this delivered path.

Every CSV cell is quoted and escaped. Formula-like source text, including whitespace-prefixed formulas, is neutralized; validated numeric amounts keep their decimal sign and precision. A BOM preserves spreadsheet recognition of French UTF-8 text. Actual browser testing exposed that the server-action text transport removed that leading marker, causing an honest integrity rejection. The action now sends base64-encoded bytes; the browser decodes them, verifies SHA-256 and creates a Blob from the exact bytes. The audit hash matches the downloaded file, including its BOM and CRLF line endings. This is a content-integrity check, not a digital signature or financial approval.

## User instructions and required information

1. Open /en/dashboard/purchases/payables/history or /fr/dashboard/purchases/payables/history through your authorized Purchases navigation. Set the activity lane and document-date range. A supplier page can supply the supplier filter; the dialog shows its ID. Obtain the intended period and supplier from the AP task or your responsible AP owner, not from guessed identifiers.
2. Choose Download CSV / Télécharger CSV. Review the scope and limits. This downloads all matching rows, including records outside the visible page and archives. Date filters follow the organization's displayed timezone and select documents; current settlements are not a historical-balance reconstruction.
3. Choose Download CSV in the dialog. If prompted, enter your own current password and confirm. The existing password-verification service checks it; the form does not persist it. If attempts are rate-limited, wait the displayed interval. You do not need an approval ID or a new signature for this ordinary authorized export.
4. Check your browser downloads. The confirmation means the browser download was started, not that a file was saved to your chosen location. The filename and CSV manifest contain the watermark reference. Keep the file unchanged if you need to compare its SHA-256 with its audit record.
5. If access is denied, ask the organization administrator to review both AP reading and reports.export (or its recognized aliases), the current workspace and module availability. Obtain role assignments from the existing organization role controls. The form cannot grant permissions. If the file is too large, narrow dates/supplier; no subset is presented as a complete export.
6. If generation or transport fails, the filter scope remains available. Retry creates a current extract and a new generation audit if successful. No invoice, payment or ledger operation is repeated by exporting. If the dialog closes before completion, it discards the late browser response; an already-generated audit may still exist.

For an unavailable monetary value, the AP owner must trace the source invoice/payment, allocation/credit and supplier-ledger evidence. Obtain source IDs and evidence references from the authorized history and underlying records. Do not fabricate ledger entries or replace UNAVAILABLE with zero. A legal/accounting certification, full supplier balance, historical trial balance or professional signature must come from the separately governed workflow and evidence; this CSV does not supply them.
