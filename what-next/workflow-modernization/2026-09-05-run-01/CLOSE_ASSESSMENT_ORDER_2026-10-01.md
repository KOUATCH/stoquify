# Current assessment admission and certification ordering

Primary workflow: FA-CASH-COMMAND. Supporting workflow: FA-CLOSE-PACK. The full 17-family modernization objective remains active. Previous turn classification: progress, with delivered and verified current-assessment recovery and count invalidation. This milestone does not replace either workflow's full closure checklist.

## Bounded acceptance established before implementation

1. Publishing a new assessment and certifying the current assessment serialize on the same tenant/period boundary, acquired before the existing run lock. Evidence collectors do not hold the publication lock.
2. Writer transactions explicitly use Read Committed so lock waiters observe committed publications after acquiring the lock.
3. Publication time comes from the database after the lock, at the persisted millisecond precision. It must be later than the existing maximum; ambiguous or regressed clocks reject without publishing a hidden older RUNNING run. No fabricated increment, historical rewrite or use of caller-supplied assessment time as publication order.
4. Certified export requires the requested run to be the unique newest assessment, considering every status and independent voiding. Existing authority, fresh authentication, separation of duties, setup, source freshness and statutory limitations remain effective.
5. Historical reads, draft export and retained certified artifacts remain available under existing permissions. Certification denial produces no new certificate or alteration of retained evidence.
6. Dashboard and Close proof reads qualify selected evidence as current, historical, ambiguous or voided within one tenant-period snapshot; current certification availability agrees with the authoritative writer. EN/FR guidance supports deliberate refresh/retry.
7. Actual two-connection checks prove creator-first and certifier-first waits, opposite completion order, tenant/period isolation, clock/order failures and preserved existing invalidation serialization. Actual service operations establish the tested claims; synthetic rows alone do not prove assessment completion or approval.
8. Focused regressions, action/error transport, UI recovery, changed-file lint, existing TypeScript and applicable static gates are recorded with source bindings. Failed attempts remain retained. No overall workflow closure or professional/release approval is implied.

## Remaining boundaries

Producer discovery can still miss a newly published run: a source writer may discover old IDs, a creator publish and read pre-commit source, and the writer invalidate only its captured IDs. This milestone's creator/certifier lock does not universally solve that race. Participating producers need a separately verified period-lock protocol and global multi-period ordering. Inventory fingerprint rechecks are not proof of all-domain freshness.

Historical unavailable evidence still needs source-bound replacement linked to the accepted finding and authoritative collector output. Finding acceptance text alone is insufficient. Full Cash source/authority and lifecycle reconciliation, interrupted/outbox delivery, genuine country/payroll evidence, inherited localization/accessibility/hydration and representative production latency remain open.

No migration, live customer activation, payment, external message, deployment or X1 clearance is authorized by this implementation. System certification is internal evidence only; statutory authority and expert-review requirements remain separate.

## User and operator guidance

Open `/en/dashboard/accounting/close` or `/fr/dashboard/accounting/close` and select the accounting period. A historical assessment is retained for review and draft export. Use **Open latest assessment** when offered, review the refreshed controls, and deliberately request certification only when eligible. A refusal refreshes evidence but never automatically submits another export. Existing identity verification and a different authorized certifier remain required.

If latest assessments share a creation time, run a fresh assessment and review it. If publication time is unavailable or has not advanced, wait briefly and retry; persistent failure requires the operator to inspect database clock health and any future-dated imported records. Do not edit old creation times or clear voiding/status fields to force admission. **Certification recorded** means current internal system evidence exists for that assessment; it is neither a statutory approval nor an automatic reissue of an earlier document.

No new schema or migration is required. Local verification changes only guarded synthetic fixtures. Roll out the creation and export changes together to any later authorized target; mixed old/new writers do not share the new lock contract. Keep historical artifacts and audit records. A rollback must be assessed as restoring the obsolete-certification defect; pausing affected certification is preferable to silently accepting older assessments. No rollout or live activation was performed here.
