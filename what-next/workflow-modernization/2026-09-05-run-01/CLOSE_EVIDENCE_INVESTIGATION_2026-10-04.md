## Delivered behavior and limits

Previously, a reviewer saw investigation guidance but could not inspect the contradictory records through the workbench. The new **Investigate retained evidence** section retrieves a request's retained requests, responses and acceptances, with recorded dates, source references, structural discrepancies and a SHA-256 snapshot reference. The French section is **Examiner les justificatifs conservés**. It uses the existing dashboard controls, borders, spacing and warning semantics; the inspection is not styled as successful approval.

The service enforces current Close read and accountant-review permission plus module read access both before and after a repeatable-read transaction. A read-only module can retain review access. The request and finding are anchored to the current tenant and selected period. Records attached to that finding are not filtered by malformed metadata or inconsistent period/run references, so those discrepancies remain visible. Foreign linked records are not followed. Raw metadata, actor identifiers and audit network details are withheld.

The snapshot hash binds the retained source fields, finding state, bounded assignment audit history and current assignment projection. It is a reference to an observation, not a signature, permission, approval or persisted recovery decision. An unchanged read yields the same hash. The view caps both evidence rows and assignment audit rows at 100, labels truncation explicitly and reports displayed counts. Structural diagnostics do not certify the records or the entire historical chain. Current recipient resolution still validates only the current transition and predecessor.

No record is edited, discarded, superseded or selected as canonical. Existing conflict guards and exact replay remain effective. Controlled resolution still requires a durable proposed decision, independent authorization, current authority/evidence revalidation, retained superseded records and consistent consumption by queues, tracking and writers. Inspection is its prerequisite, not its replacement.

## User and operator instructions

Open `/en/dashboard/accounting/close` or `/fr/dashboard/accounting/close`, select the accounting period and use the investigation section. You need a current same-organization account with Close read and accountant-review permission, and module read access. Copy the request reference from retained request history or obtain it from the colleague reporting the issue. Enter that reference and select **Inspect records** / **Examiner les enregistrements**.

Review the original wording, links, dates, discrepancies and snapshot reference. The original requester need not operate this read-only inspection. A failed read clears the previous results and retains the input for retry; it does not mean there are no records. Changing period invalidates an outstanding read. The main evidence response/review draft remains separate from this inspection.

For an investigation handoff, provide the request reference, selected period, discrepancy description and snapshot reference through your existing internal review process. Do not treat the hash as an approver's identity or enter it as an issued approval record. The application has not yet implemented the controlled resolution decision; do not delete evidence or repeatedly submit acceptance to work around that missing step.
