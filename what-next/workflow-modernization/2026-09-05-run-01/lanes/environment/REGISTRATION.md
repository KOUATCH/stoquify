## Delivered behavior

Input bounds and normalization now live in the service. Guided acceptance must be boolean true and the password confirmation must match. Account creation commits organization, own administrator role, user, credential/history, optional first branch, referral conversion and AUTH_REGISTERED audit together. Audit or credential failure rolls everything back. No signing authority, subscription, country readiness, verified email or live entitlement is inferred from setup choices. An explicit empty capability selection stays empty in the organization and audit.

Both forms use hydrated POST, masked passwords, associated labels, focusable failure feedback, draft recovery and a synchronous pending fence. The hook never retries creation automatically or infers success from an incomplete handoff. Actual rate-limit responses include the server's remaining wait, rendered in EN/FR. Guided French copy and option labels are translated without changing canonical submitted values. Referral-bearing entry pages use no-referrer/noindex metadata.

The browser reproduced a critical interaction defect: the guided Continue button could become the submit control during the same activation, creating the workspace before an explicit review confirmation. Distinct button identities now keep navigation and creation separate. Current EN/FR browser proof verifies that reaching review creates no records and that an interrupted submission preserves the draft.

## What the user does

Use the guided route to enter business context, choose a setup role, supply company and administrator details, then review suggested capabilities. Remove any suggestions you do not want; leaving all unchecked records an empty selection. These are setup requests, not activation approvals. Press Create workspace only after reviewing. The three-step route retains its simpler organization and account setup.

After confirmed creation, continue to the email-verification page. If delivery has not arrived, use its existing request-code process. The local verification environment deliberately sends no email. A lost response retains your entries; check for a verification message or try signing in before attempting another organization. A rate-limit message gives the real wait interval. Do not refresh as a substitute for confirming whether creation succeeded.
