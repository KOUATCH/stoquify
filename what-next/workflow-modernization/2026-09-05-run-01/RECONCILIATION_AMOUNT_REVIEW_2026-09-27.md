## Defect and correction

The owned signed-source fixtures reproduced one 100.25 XAF payment with an unchanged match and a fully resolved corroborating-source case, while a new certificate reported suspense 100.25 and external amount 200.50. Those figures came from cumulative run columns, not a calculation of current unresolved cases. Adding callback and statement amounts also counted two evidence records for the same payment. Baseline: lanes/environment/corroborating-total-observation-490cf975-afbc-41a8-b678-00f3560d546d.json.

The existing complete evidence-manifest query now optionally produces a decimal-precise amount summary for preparation/signing. It groups by currency and separates internal payment records, provider callbacks, statement lines, accepted match allocations and unresolved suspense. Resolved/written-off cases are excluded from unresolved amounts. Null amounts remain unavailable; invalid currencies, negative/nonfinite amounts and unknown suspense states fail the summary. No sum crosses currencies or source categories. Values are gross records in both directions, not net balances or ledger-certified exposure.

The independent sign-off preview displays this source-derived breakdown in EN/FR, with an explicit warning that callbacks and statements can describe the same payment. A blocked review does not present cached cumulative columns as current verified amounts. Recent-run copy now identifies its counts as recorded at matching and directs the reviewer to current amounts, removing the misleading scalar suspense display.

New certificates use version 3: amountSummary contains the reviewed current breakdown; recordedRunTotals retains the old header values with the explicit basis CUMULATIVE_RUN_CAPTURE_NOT_CURRENT_EXPOSURE. No earlier certificate, run header or evidence hash is rewritten. The retained-signature verifier accepts audited versions 2 and 3. Existing source-version identity remains stable; the full evidence revision binds the new review to the amount summary. New signing/reopening/export paths remain under the same authority, period and independent-review controls.

## Operation and rollout

Open /en/dashboard/finance/reconciliation or /fr/dashboard/finance/reconciliation and review a ready run for independent signing. Read each currency separately. Compare payments with their callback/statement evidence without adding categories together. The unresolved-suspense figure comes from current nonterminal cases. Any unavailable amount needs source review; it is not zero. Existing case investigation, preparation, signing and recovery actions remain the route to correction.

No new user input, organizational approval, database migration or backfill is required for this code change. Existing certificates retain their original content and semantics. Export consumers must check the certificate version: v3 readers use amountSummary for the current review and recordedRunTotals only for historical capture. Native application review and JSON export are tested. External consumers that assume a v2 totals shape need a parser update before rollout. Never rewrite a signed certificate to adapt its format. Rollback preserves existing signed files; an older reader may require an update to interpret v3 records, so application rollback must retain v3 read compatibility.
