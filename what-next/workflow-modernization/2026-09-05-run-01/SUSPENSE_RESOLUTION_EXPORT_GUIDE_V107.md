## Operator procedure

Open `/en/dashboard/finance/reconciliation` or `/fr/dashboard/finance/reconciliation`. In the suspense queue, open **Resolution and recovery / Résolution et réouverture**. Already-final items can be inspected through retained records. Each history entry now offers **Download evidence / Télécharger les preuves** to users who have export permission.

Choose the specific proposal or decision. Complete password step-up if requested, then explicitly retry. Authentication alone does not issue an export. If the page is refreshed or the browser handoff fails, the exact request remains saved for retry. The server checks current authority and retained financial evidence again; a successful retry returns the original receipt and bytes. Verify the file in your browser downloads. The displayed success message confirms only that a verified file was handed to the browser.

| Information needed | Source | Person responsible |
| --- | --- | --- |
| Organization and suspense item | Current authenticated workspace and queue/retained record | Operator |
| Proposal or decision to export | Resolution/reopening history and its recorded time/reason | Authorized reviewer |
| Export authority | Existing role permission `payments.export`, plus reconciliation and journal read permissions | Organization administrator |
| Fresh authentication | Current exporter's own password | Exporter |
| Revision and retry key | Generated by the application; do not type or replace manually | Application |
| Receipt and SHA-256 | Export result and immutable server receipt | Application; recipient verifies bytes if needed |

Do not share credentials or substitute another person's identity. Export authority is separate from proposal or approval authority. A hash detects changed bytes; it does not identify an independent signer or create a statutory approval.

## What the file contains

The private JSON file distinguishes the selected proposal/decision from the original posting, clearing journal and any later reversal. It contains scoped record IDs, times, reasons, actors, selected financial lines, exact monetary strings, source links and retained hashes. Recovery records include the original resolution lineage. Later original-posting corrections are verified against their retained cycle evidence, so history does not rely on the item's current active journal alone.

Raw provider payloads, unrelated source metadata, prior certificate payloads, journal descriptions and raw dimension objects are excluded. Dimension hashes and necessary financial linkage remain. These files still contain financial evidence and should be stored under your organization's normal access policy.

The export preserves the status observed when that file was first prepared. Replaying the same request returns those original bytes; it does not silently rewrite the prior observation. Request a new export if you need a new observation of the same record. A historical proposal is not approval, and an old approval is not current settlement confirmation after reopening.
