# HR-16 operations and recovery

Apply the additive `20261024160000_hris_personal_correction_cases` migration after all HR-15 migrations using the established release schema stage. This session applied and replayed it only on the owned synthetic PostgreSQL. The case table reuses PayrollEmployee; native profile approval writes its business event, audit and case outcome in one transaction. Existing Prisma transactions use parameterized SQL for the new table, so this slice does not require replacing a running generated client binary.

Before a real pilot, the employer must supply reviewed `HRIS_PERSONAL_CORRECTION_POLICIES_JSON`: organizationId, version, allowedFields (displayName and/or legalName), reviewerId, supportLabelEn/supportLabelFr, approvalReference, effectiveFrom/effectiveTo (UTC ISO). The reviewer must be active with current HR management authority; legal-name review additionally needs protected document read authority. No actual employer policy or owner has been configured here. Legal names require a reviewed, valid identity original under HR-15 provider/policy controls. Salary, bank, account identity and employment status remain with their existing owners.

Use `/[locale]/dashboard/people/me/corrections` for employees and `/[locale]/dashboard/people/corrections` for HR. Own-mode time/document operations derive employee identity from the current authenticated account even when that account has HR powers. An unlinked/revoked account receives no employee data. Configure a shared workstation path if employees have no personal smartphone.

Recovery: retry an uncertain mutation with its exact key and payload; changed payloads conflict. After a confirmed mutation followed by list failure, refresh the list only. Return stale/source-changed cases for amendment. A configured replacement reviewer can be assigned through a recorded REASSIGN decision. Do not edit history or rewrite published payroll records.

Rollback: remove/expire correction submission policy to stop new submissions/amendments/approvals; keep read/status/history and independent return/rejection available. Do not delete the additive table or supporting originals. HR-15 controls continue to govern document availability. Preserve synthetic evidence and use the established release/pilot gate before deployment. This session enabled no external provider, notification, real invitation, employee-account revocation or production schema change.
