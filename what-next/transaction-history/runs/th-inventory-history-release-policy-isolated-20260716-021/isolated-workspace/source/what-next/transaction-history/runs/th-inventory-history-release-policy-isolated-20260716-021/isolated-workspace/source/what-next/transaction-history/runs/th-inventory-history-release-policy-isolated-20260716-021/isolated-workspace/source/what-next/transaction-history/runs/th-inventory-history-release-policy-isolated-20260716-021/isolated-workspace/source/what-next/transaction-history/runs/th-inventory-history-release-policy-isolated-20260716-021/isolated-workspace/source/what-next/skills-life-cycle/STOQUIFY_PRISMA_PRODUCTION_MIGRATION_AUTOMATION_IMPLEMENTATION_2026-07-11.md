# Stoquify Prisma Production Migration Automation Implementation

Date: 2026-07-11

Status: Repository implementation complete. Production execution remains provider-bound because this checkout has no Vercel CLI, project link, or injected production database target.

## Scope

Restore migration automation without allowing local builds, ordinary preview deployments, shared preview/production databases, unreviewed destructive SQL, or copied production credentials to mutate the production schema.

## Implemented

- Added `scripts/prisma-production-migration-gate.js` as the service-independent migration deployment boundary.
- Added production-only automatic `prisma migrate deploy` execution after the release-secret preflight and before application compilation.
- Kept local and ordinary Vercel Preview builds mutation-free by default.
- Required explicit target attestation for exceptional staging or isolated-preview migration runs.
- Added PostgreSQL URL validation and rejection of local database targets without printing URLs or credentials.
- Added destructive-SQL scanning for DROP, TRUNCATE, DELETE, column-type changes, and table/column renames.
- Added `prisma/migration-risk-approvals.json`; approvals bind reviewer evidence and risk rules to the exact SHA-256 migration file hash.
- Wired static migration safety into `policy:gates`, production target validation into `verify:release`, and safe execution into `npm run build`.
- Added the migration readiness artifact and production database condition to the leadership release-evidence ratchet.
- Updated the canonical deployment architecture and migration runbooks.

## Release Conditions

The release index now exposes three provider-owned conditions:

1. `PUBLIC_IDENTITY_ABUSE_HASH_SECRET`
2. `AQSTOQFLOW_RECEIPT_TOKEN_SECRET`
3. A non-local PostgreSQL `DATABASE_URL` injected into the production deployment

No real production migration was executed in this run. That is intentional: no Vercel CLI or linked project was available, and production credentials were not copied into the workstation.

## Safety Boundary

Prisma recommends `migrate deploy` for production and staging and recommends invoking it through CI/CD rather than temporarily setting a production URL locally. Vercel Preview deployments can share the Production database if environment variables are configured carelessly, so Stoquify previews now skip migration by default and require an explicit `preview-isolated` attestation to opt in.
